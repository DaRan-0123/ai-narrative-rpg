# 故事生成器设计方案（v1 简单版）

> 对应 TODO.md 第 3 项"故事生成"。**2026-07-28 已实施并真实验证通过**（老陈存档首批2条剧情线质量优秀）。本文档为设计原稿。
> 定位：新增 P11"故事师"，负责长期剧情线，让叙事有方向感而不是纯粹被动反应。

---

## 一、要解决的问题

现状：P1 每轮被动响应玩家输入，剧情没有长期方向。NPC 有 plot_hooks（P6 生成）但**没有任何机制去兑现它们**——伏笔埋了永远不收。

## 二、核心设计：剧情线档案 + 定期回顾

### 数据结构（`saves/{存档}/story_threads.json`）

```json
{
  "threads": [
    {
      "id": "thread_001",
      "title": "银徽制服打听者",
      "summary": "有穿银徽制服的人在旅店打听老陈，身份目的不明",
      "stage": "发酵中",
      "next_beat": "打听者再次现身，留下约见的口信",
      "involved": ["玛莎", "老陈"],
      "status": "active",
      "created_round": 9,
      "updated_round": 15
    }
  ]
}
```

- 同时活跃 **2-3 条**，多了驾驭不住（v1 硬上限 3 条 active）
- `next_beat` 是 P1 的"下一个剧情节点提示"——**是方向建议，不是强制剧本**
- status：active / resolved / dormant（ dormant 的可被重新激活）

### P11 故事师（pro 模型）

**触发：每 10 轮一次 + 一条剧情线 resolved 时立即补一次**（低频，成本可忽略）。

输入：现有剧情线 + 最近 10 轮历史摘要 + 全场 NPC 的 plot_hooks + 最近 30 条 known_facts + 世界观。

输出：更新后的剧情线列表（JSON）：
- 推进：根据最近剧情，更新 stage 和 next_beat
- 收尾：玩家已解决/彻底偏离的线标 resolved
- 新生：从 NPC plot_hooks 或近期事件中孵化新线（保持 active ≤3）
- 蛰伏：玩家长期不碰的线标 dormant（不删，可复活）

### P1 注入

P1 prompt 加【剧情线】块（放在【元设定】附近的固定区块，缓存友好）：

```
【剧情线】（供叙事方向参考，玩家行为优先，不可强制）
- 银徽制服打听者（发酵中）：下一步→打听者再次现身留下口信
- 东区药贩的货源（蛰伏中）：……
```

规则写进 P1_SYSTEM：**剧情线只作背景推力，玩家明确走向其他方向时服从玩家**。

## 三、每轮成本

- 平时：零（P1 注入剧情线块约 60-100 token，两条线）
- 每 10 轮：一次 P11 pro 调用（输入中等，输出 <500 token）
- 月成本量级：几分钱

## 四、改动清单

| 文件 | 改动 |
|---|---|
| `src/prompts.py` | 新增 P11_SYSTEM / build_p11_user；P1 加【剧情线】块 |
| `src/game_state.py` | story_threads 读写、active 筛选 |
| `src/save_manager.py` | story_threads.json 持久化（模仿现有存档方法） |
| `src/ui/game_window.py` | 每 10 轮触发 P11（异步，不阻塞回合）+ resolved 即时触发 |
| 初始化 | 新存档创建后调一次 P11 生成首批 2 条剧情线（种子来自 initial NPC 的 plot_hooks） |

## 五、明确不做（v1）

- 不做强制剧本/章节结构（玩家自由度优先）
- 不做剧情线之间的复杂依赖图
- 不做结局判定（resolved 只是"这条线完了"，不是游戏结局）
- 不用 flash：剧情线质量直接决定游戏质感，值得 pro

## 六、验证方式

1. 用老陈的旅途：手工构造 10 轮历史（或利用现有 15 轮 action_history），真实调一次 P11，检查产出剧情线质量——是否用了玛莎记忆里的"银徽制服打听者"伏笔、巴托的"还人情"伏笔
2. P1 注入后跑一轮，检查叙事是否自然带向 next_beat 且不强推
3. 连续两轮玩家故意反着走，检查下一轮 P11 是否把线标 dormant/调整而不是硬拉回来
