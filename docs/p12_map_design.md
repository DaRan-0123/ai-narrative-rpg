## 一、要解决的问题

玩家驱动叙事中"我在哪 / 我能去哪 / 世界有多大"三个空间感知缺失：

- 地点此前不是数据实体，只是 `known_facts` 里的扁平文本（`saves/*/locations/` 目录为空占位）
- `current_location` 是自由文本字符串，系统不知道任何两地之间的关系
- 世界边界 = 叙事碰巧提到的地方，之外是虚空 → 世界观显得狭窄

## 二、总体方案：P12 地图师 + 网格坐标

新增第 12 个 Prompt 角色 **P12 地图师**：新地点出现时，由它把叙事中模糊的空间描述落实为**网格坐标**，程序按坐标自动渲染地图。

- AI 出"提案"（坐标或远方判断），程序校验、落库、渲染
- **落库即锁定**：一个地点一生只定位一次，第一次合法输出即永久真相
- 单层网格先行（本城一张图），世界分层以后再说

## 三、坐标系统规则

| 项 | 规则 |
|---|---|
| 网格 | 21×21，x、y ∈ [-10, 10] 整数 |
| 轴向 | **+x = 北，+y = 东** |
| 尺度 | **1 格 = 固定距离（客观值写进系统提示）**——具体数值待定：用户示例"1格=5km"偏行省级，本城地图建议 200~500m/格，实施时定 |
| 原点 | (0,0) = 城市中心参考点（开局地点或城市地标） |

## 四、用户定案（2026-08-03，四条）

1. **碰撞不做程序仲裁**：P12 输入包含全部已有地点+坐标，AI 不会明知有物还撞格；程序只留一行**断言**——真撞了直接报错，不悄悄挪
2. **越界/格式错误 → 直接报错给用户，不重试**（让用户第一时间看到）
3. **只有玩家真正到过的地方才上地图**：`current_location` 实际出现过的地点才分配坐标、才渲染；"只听说过"的地方不进图（砍掉灰节点机制）
4. **尺度客观化**："1 格 = X" 写死进系统提示，不用"很远/很近"这类主观词

## 五、远方机制（far）

- P12 输出为二选一：`{"x", "y"}` **或** `{"far": 八方位之一}`
- AI 判断地点太远、不可能落在本城网格时输出 `far`（北/东北/东/东南/南/西南/西/西北）
- 程序在地图边框外对应方位显示标签（如"北 · 风啸高原"）——世界宽广感的来源，且地图本身永远干净
- 远方地点日后若玩家真的前往，再正式分配坐标上地图（或届时引入第二张图，未定）

## 六、P12 输入输出（实验验证版）

**模型**：lightweight（flash），temp=0.3（与 P3 一致；可再调）

**输入**：
- 坐标规则 + 尺度（系统提示）
- 全部已上地图点清单（名字, x, y, 一句话描述）
- 叙事原文片段（涉及新地点的段落）
- 主角当前位置（`current_location`）

**首要前提（2026-08-04 用户指正）**：P12 的第一条判断不是"往哪放"，而是"**主角是否身临其境**"。叙事会提及大量地点，只有主角**实际身处/抵达**的新地点才分配坐标；仅仅被提及、主角未到的地方**不分配、不上图**。

**输出**（严格 JSON，三选一）：
```json
{"name": "地点名", "label": "地图显示名（7字内）", "x": 7, "y": -3, "icon_subject": "建筑外观描述", "reason": "依据原文哪句话（30字内）"}   // 主角身处此地 → 坐标
{"name": "地点名", "label": "地图显示名（7字内）", "far": "东北", "reason": "依据（30字内）"}              // 遥远之地 → 图外标签
{"none": true, "reason": "主角未到达，仅被提及（30字内）"}                // 不上图（正常结果，非错误）
```

**补充规则（2026-08-04 接入后用户两条修订，已写入 P12_SYSTEM 与程序）**：
1. **首点锚定**：已有地点为空时（第一个上图地点），坐标一定是 (0,0)
2. **label 短名**：`name` 仍原样回显做装傻校验；另输出 `label` 作为地图显示用名，提取地点最核心叫法、建议 7 字以内（如"安塔利亚南区，港湾憩所旅店一楼大堂"→"港湾憩所旅店"）。程序侧：label 超 7 字只提示不拦截（"建议"非强制）；label 缺失时兜底取地名最后一个逗号分段。注册表以完整地名为主键（程序门不变），label 仅供渲染显示

**icon_subject（2026-08-04 定案：P12 兼任图标题材供给）**：
- 写**建筑外观**（主角在室内时也描述房子外观，图标画的是建筑不是房间）
- **颜色材质全显式**（沿用立绘踩坑教训："石砌教堂，灰色尖塔，拱形长窗，棕色木门"）
- 叙事给了外观细节用叙事的；没给就按地点类型给城市常见形态
- 非建筑地点描述主体物（"中央有喷泉的小广场"）
- 无人物、无文字招牌
- 程序侧负责拼接固定**构图块**（单体/45度/居中/白底/无地面/无边框）与**风格块**（手绘地图风/粗墨线封闭轮廓）——P12 只给题材，风格统一由程序模板保证
- 生成时机：坐标落库即懒生成（z-image-turbo，0.1元）→ 容差28抠图 → 缓存 `locations/{id}/icon.png` 终身复用

## 七、程序校验清单（每条都对应真实踩坑）

| 校验 | 不通过时 |
|---|---|
| JSON 可解析、为对象 | 报错给用户 |
| 坐标为整数 | 报错给用户 |
| 坐标在 [-10,10] 内 | 报错给用户（定案2） |
| 不与已有地点同格 | 报错给用户（定案1断言） |
| far 值在八方位枚举内 | 报错给用户 |
| **name 字段 == 待安置地点名** | 报错给用户——防"装傻"：实验中发现 flash 偶尔谎称"未提供输入"并甩出 far=北 跑路（2026-08-04 第二轮，翠石大厦案例 2/3 次） |
| **坐标输出时 icon_subject 非空** | 报错给用户——图标提示词的题材来源，缺失则图标管线断料（2026-08-04 扩展） |

## 八、实验验证记录（2026-08-04，两轮共 28 次真实 flash 调用）

素材：`saves/老陈的旅途` 真实叙事片段（第12/14/15轮）+ 1 条合成远方案例。

| 案例 | 线索类型 | 结果 |
|---|---|---|
| 接头棚子（"码头第三排最东边"） | 有明确参照物 | **3/3+3/3 完全一致 (3,4)**，可信任 |
| 码头仓库区（"下巴朝东北点了点"） | 只有方向 | 方向 6/6 全对（都落东北象限）；具体格子飘（(7,7)/(6,5)/(4,4)；第二轮收敛 (5,5)） |
| 翠石大厦（"正门五十步外"） | 亚格距离无方向 | 自觉避开 (0,0) 放相邻格，行为合理；第二轮暴露"装傻"失败模式 |
| 贫民窟（零线索） | 无（且属误设计，见下） | 区域直觉一致（"近码头"），具体格子散（(-1,-1)/(-3,-2)/(-8,-8)） |
| 风啸高原（"北方千里之外"，合成） | 远方 | **4/4 全部 far=北**，稳定 |

> **实验设计更正（2026-08-04 用户指正）**：案例"贫民窟"为**误设计**——素材是"耳闻式"（老陈从未去过贫民窟），按定案 3 它本不该作为坐标安置任务。其离散结果部分是这一错误设计的产物：零线索 + 输入无码头锚点时，AI 只能采样城市先验，落点自然散。修正后此类输入应走第六节"none 拒答"路径（反向测试待补）。风啸高原案例仍有效——它测的是 far 输出格式，非安置。

**关键结论**：
1. 格式/越界/碰撞/远方：**可靠**（两轮 28 次仅"装傻"一种失败，可用校验拦截）
2. 相对定位（有锚点）：**稳定可复现**
3. 距离估计：模糊但都在合理区间；**落库即锁定**使"飘"不影响系统一致性
4. **锚点积累自强化**：实验是单锚点最差条件；真实使用中已上地图点越多，新地点定位被约束得越稳
5. 待改进：prompt 加"市区典型地点间距 2-5 格"参照，收敛距离估计（实施时做）

## 九、与既有系统的关系

- **P1-P11 全部不动**，P12 为新增独立角色，沿用"P3 式"轻量判定哲学
- **触发（草案）**：双重门——**程序门**：每轮对比 `current_location` 与已上图注册表，名字未注册才考虑触发；**P12 门**：确认主角确实身处新地点（第六节首要前提），仅被提及则输出 none 不落库。双重门都过 → 校验 → 落库 → 地图刷新。（是否让 P3 参与提取，待定）
- **地名注册表（草案）**：名字字符串 → 节点ID；别名合并策略未定
- **地图渲染（草案）**：程序按坐标画网格；建筑图标走 `archive/galgame_portraits/docs/galgame_art.md` 第七节的"白底生成+容差28抠图"管道，生图模型 **z-image-turbo**（2026-08-04 定案，0.1 元/张，`bailian_gen.py --model z-image-turbo`）；远方标签列图外八方位
- **P1 回喂（草案）**：已上图地点的相对位置可注入 P1【当前位置】块，让叙事自带空间锚点（"码头在你东北方"）——范围待定

## 十、地图原型排版定案（2026-08-04 用户逐条评审确认）

原型脚本 `map_test/proto_map.py`（生成），成品 `map_test/output/proto_map.png`，查看器 `map_test/proto_map_viewer.py`。以下为用户看过效果图后逐条拍板的规则：

1. **网格**：21×21（±10），细线每格、粗线每 5 格
2. **背景**：AI 直出的暗色牛皮纸质感图铺满网格区（z-image-turbo，`parchment_dark_1.png`，提示词要点"偏暗深暖黄、昏暗烛光下的旧纸"）——**不要地区轮廓**（试过一版轮廓背景，用户否决），也不用代码调暗（试过 72% 亮度，用户否决，改 AI 直出）
3. **图标**：边长 0.4 格，**渲染前先裁掉抠图 PNG 的透明边距**（抠图画布 1024² 但建筑本体只占约 70%，不裁会小一圈——2026-08-04 实测踩坑），**底部对齐坐标点**。0.4 格经"四边相邻"实测验证不重叠（用户亲自确认）
4. **地名标签**：无底、无框、纯文字（浅色描边保证可读），**贴在坐标点上**（即图标正下方），不下移；字号 9
5. **坐标不显示**：无轴刻度、无格内数字；方向用左上角「北 ↑」罗盘角标表达
6. **玩家标记**：红色圆点 + 名字标签（标签在点上方）
7. **远方标签**：地图对应方位边缘处，格式「⇧ 远方 · 北 —— 风啸高原」
8. **无道路**（用户明确要求先不加）
9. **缩放独立于生成**（2026-08-04 用户明确）：地图的「编辑生成」和「缩放」是两个单独的系统，互不影响
10. **查看器架构**（2026-08-04 用户定案）：**生成出图 + 纯图片查看器**。生成系统（matplotlib）每次地图内容变化时重新渲染高清 PNG；查看器是 tkinter 图片查看器（`proto_map_viewer.py`），只认 PNG，零 matplotlib 依赖、与游戏主程序同技术栈。查看器规则：滚轮以鼠标为中心缩放、左键长按拖拽平移（只挪画布项不重采样，零开销）、**打开默认 100% 原大**（"适应窗口"会把图标缩没，用户否决）、**必须启用 DPI 感知**（Windows 显示缩放下不启用会被系统模糊拉伸，小图标糊没——用户实测踩坑）
11. **废弃**：`proto_map_interactive.py`（matplotlib 交互版）——缩放重绘不跟手、与查看器混淆两次，被方案 10 替代，留档不删
