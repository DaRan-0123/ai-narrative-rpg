# NPC 记忆系统设计方案

> 对应 TODO.md 第 1 项"NPC记忆"。2026-07-28 设计，待用户评审，未实施。
> 依据：src/game_state.py、src/prompts.py 现状（P1 注入在场NPC档案+最近3条心理；P4 每轮追加 psychology_log）。

---

## 一、现状与问题

| 现有机制 | 局限 |
|---|---|
| 静态档案（性格/背景/关系） | 创建后不变，不随互动演化 |
| psychology_log（P4 每轮追加心理状态） | 是"当前情绪"的滚动流水，不是"事件记忆"；P1 只看最近 3 条 |
| known_facts（全量事实） | 玩家视角的客观事实，不属于任何 NPC，NPC 无法"记住与自己有关的互动" |

**后果**：玩家替 NPC 挡过刀、骗过 NPC、答应的事没做到——几十轮后 NPC 完全不记得，行为没有连续性。

## 二、设计目标

NPC 能记住与玩家的**具体过往互动**（情景记忆），并让这些记忆：
1. 影响 P1 叙事中该 NPC 的言行（提起旧事、翻旧账、态度有依据地变化）
2. 为 P4 心理演化提供连续依据（不是每轮孤立判断）
3. token 成本可控（记忆无限增长是已知风险，见 HANDOVER 7.2）

## 三、数据结构

NPC 档案新增 `memory_log`（与 `psychology_log` 并列，职责分离）：

```json
{
  "memory_log": [
    {
      "round": 12,
      "event": "玩家垫付了 3 银币替他赎回药箱",
      "perception": "觉得这人虽然穷但靠得住，欠他一次",
      "importance": 4,
      "tags": ["恩惠", "金钱"]
    }
  ]
}
```

- **event**：客观发生了什么（一句）
- **perception**：NPC 的主观解读（一句）——这是让行为可信的关键，同一事件不同 NPC 记住的角度不同
- **importance**：1-5，由 AI 评估，决定检索优先级和巩固时的去留
- **tags**：便于将来按主题检索（可选）

分工：`psychology_log` = 当前心理状态（滚动、可淘汰）；`memory_log` = 情景事件（累积、经巩固压缩）。

## 四、记忆写入：扩展 P4（零新增调用类型）

P4 本来就在 NPC 有互动时运行（pro 模型）。输出 JSON 增加一个字段：

```json
{
  "psychology_change": "...（原有）",
  "memory_entry": {
    "event": "...", "perception": "...", "importance": 3, "tags": ["..."]
  }  // 本轮无事可记则为 null
}
```

- P4 prompt 增加指引：只记"对 NPC 有意义的互动"，日常寒暄记 null；importance 标准：5=救命/背叛，4=大恩惠/大冲突，3=有意义的交谈，2=轻微摩擦，1=一面之缘
- 成本：P4 输出多约 60-100 token/次，无新增 API 调用

## 五、记忆读取：注入 P1（限量检索）

P1 的【在场NPC档案】块中，每个 NPC 追加【记忆】小节：

- **选取规则（代码实现，非 AI）**：最近 2 条 + importance 最高的 2 条（去重后 ≤4 条），每条限制一句话
- 格式：`- [记忆] 玩家垫付药钱 → 觉得他靠得住，欠他一次`
- 成本：约 40-80 token/在场 NPC，可控
- P4 调用时输入**全量** memory_log（它本来就是 pro 调用且频次低，让心理演化有完整依据）

## 六、记忆巩固：防无限增长（懒触发）

单个 NPC 的 `memory_log` 超过 **30 条**时触发一次巩固（flash 轻量模型，异步不阻塞回合）：

- 把 importance ≤2 且较早的记忆合并成一条"时期概述"（如"第5-20轮：玩家多次来买药，渐渐熟络"）
- importance ≥3 的原样保留
- 巩固后该 NPC 记忆压回 ~15 条以内

频次极低（每个 NPC 几十轮才一次）、flash 模型、成本可忽略。

## 七、实施改动清单

| 文件 | 改动 |
|---|---|
| `src/prompts.py` | P4 prompt 加 memory_entry 输出规则与 importance 标准；P1 在场NPC块加【记忆】小节 |
| `src/game_state.py` | 新增 `add_npc_memory(npc_id, entry)`；P1 构建时的记忆选取函数（最近2+重要2） |
| `src/ui/game_window.py` | P4 响应解析后写入 memory_log；巩固触发检查 |
| `src/prompts.py`（新增 P4C 或 P3 复用） | 巩固 prompt（flash） |

无新增 API 调用类型；总新增成本 ≈ P4 输出增量 + 每轮 P1 注入 40-80 token/在场NPC。

## 八、验证方式

1. 用模拟存档（老陈的旅途）跑：连续与同一 NPC 互动 5 轮，检查 memory_log 累积是否符合预期（该记的记、寒暄不记）
2. 第 6 轮让 P1 自由叙事，检查叙事中 NPC 是否引用记忆（如提起垫付药钱）
3. 人工灌 30+ 条记忆触发巩固，检查概述质量

## 九、明确不做的

- 不做向量检索/embedding（本地重、收益不成比例；规则选取够用）
- 不让记忆直接影响 world_facts（记忆是 NPC 主观的，事实是客观的，两套系统保持分离）
- 本期不做 NPC 之间的记忆共享（甲不会知道乙和玩家的事）
